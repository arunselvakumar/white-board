## How to run and verify

```sh
docker compose up -d
docker compose exec postgres psql -U whiteboard -c "CREATE DATABASE construction"   # existing volumes only
cp apps/construction-management/.env.example apps/construction-management/.env       # fill BETTER_AUTH_SECRET
DATABASE_URL=postgresql://whiteboard:whiteboard@localhost:5433/construction bun run --filter @repo/db migrate:deploy
bun run dev --filter=construction-management      # :3002, /api/docs
bun run --cwd apps/construction-management test
bun run --cwd apps/construction-management test:http
bun run --cwd apps/construction-management test-storybook
```

## Vercel (set up)

- Project `construction-management` (root `apps/construction-management`) builds every PR with `vercel.json` → `bash scripts/vercel-build.sh`, which runs `migrate:deploy` before `next build` on Preview and Production.
- Databases: Neon `construction-db` for Production and `construction-preview-db` for Preview (Vercel Storage), so previews never touch production data.
- Secrets generated for Preview and Production: `BETTER_AUTH_SECRET`, `CONSTRUCTION_PRIVATE_DATA_KEY`. Previews print codes to the log (`SMS_TRANSPORT=log`, `EMAIL_TRANSPORT=log`) and, from M1, accept `OTP_TEST_CODE=000000`; production never does.
- Links use the preview's branch URL; production uses `BETTER_AUTH_URL` or the project's production URL.
