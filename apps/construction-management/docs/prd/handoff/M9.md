## How it was built

- **Before fan-out (me):** the ADR, every M9 migration and the queue kernel came first, then report jobs moved onto the queue.
- **Two rounds of Opus agents in their own worktrees:**
  1. CM-901 rest, CM-902, CM-904, CM-907;
  2. CM-903, CM-906.
- **Merging:** each branch was merged into the milestone branch and type-checked after the merge.

## Found in the browser walkthrough (fixed)

- **The queue never ran in `next dev`.** The claim query built a `CASE` from nested `Prisma.sql` fragments, which webpack dev binds as values (a syntax error), so reports stayed queued. Tests and production were unaffected. The claim now passes types and leases as parallel arrays via `unnest`, and a test claims across several types.
- **Report-ready notification wording.** It showed a file slug as its body and read "Your Purchase Requests is ready". It now names the Project (or "All Projects") and adds "report" where the title lacks it.

## Stubs and gaps left for later

- **CM-905:** chat (member, group, project) and support tickets.
- **Web push in a real browser was not tried.** The in-app browser blocks notification permission; the screen shows the blocked state correctly. Try it in Chrome or Edge with VAPID keys set, on localhost or HTTPS.
- **Not in M9** (CM-0021 §7, §12): Approve/Reject from a notification, FCM/native push, email digests, scheduled automatic backups, the rest of the `modules/13` event catalogue, and moving every dashboard section onto views.
- **Large final ZIPs:** `ObjectStorage.put` takes bytes, so the final ZIP is held in memory once. A 240 s backup part starts only early in a drain; later parts wait for a poll or the daily cron.
- **Deleted accounts:** after Delete My Account the app goes to `/sign-in?account=deleted`, and the sign-in page ignores that parameter.

## How to run and verify

```sh
docker compose -p white-board-v3 up -d
DATABASE_URL=postgresql://whiteboard:whiteboard@localhost:5433/construction bun run --filter @repo/construction-db migrate:deploy
cd apps/construction-management && node_modules/.bin/next dev --webpack --port 3002
```

- **Push:** set `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT`; generate them with `bunx web-push generate-vapid-keys`.
- **Daily jobs:** need `CRON_SECRET`. Run them by hand with `curl -H "Authorization: Bearer $CRON_SECRET" localhost:3002/api/construction/queue/drain/scheduled`.
- **One heavy job at a time:** stop the dev server before a full suite; HTTP with `--maxWorkers=2`; Storybook after it.
