## How each ticket has been built

- A fresh agent per ticket reads: root `CLAUDE.md` and `AGENTS.md`; `apps/construction-management/CONTEXT.md`; the ticket's "Done when"; ADR CM-0023; `modules/14-contracts-and-billing.md` (earlier tickets' decisions bind later ones).
- Layering: `src/contracts/{domain,application,infrastructure}`, wiring in `src/composition/`, HTTP under `app/api/construction/contracts/**` with Zod models named with their context, registered in `contracts-openapi.ts`, audit events, `can()` on every command, optimistic `updatedAt`.
- Contexts never import each other; cross-context reads and writes go through ports with composition adapters (e.g. `PartyInvoicing`, `ContractsDirectory`, `MaterialIssues`).
- Migrations touch one Postgres schema each; name them `2026MMDDhhmmss_construction_<schema>_<what>`; deploy to the dev and test DBs; check `prisma migrate diff` shows no drift.
- Unique violations: `isUniqueViolation` from `src/shared-kernel/prisma-errors.ts` (never `instanceof`).
- Money is integer paise (BigInt in the domain); quantities are decimal strings.
- Forms mark required fields from their Zod schema (#112 convention).
- Commit every coherent step (`CM-11nn …` with the Co-Authored-By line); small commits survived earlier API timeouts.

### Checks before a ticket is done

`bun run check-types`; ESLint `--max-warnings 0` on changed files in batches of ~20 (one run over ~100 files ran out of memory); unit tests for the touched contexts; HTTP tests (`--maxWorkers=2`, export `CONSTRUCTION_DATABASE_URL_TEST` first — Vitest does not read it from `.env`); Storybook tests for the touched component folders (never at the same time as HTTP tests); `bun run format:check` at the root.

### Production-build walkthrough

- `bun run build` in `apps/construction-management` (the script sets a 6 GB heap; the build peaks near 5 GB), then `next start`. Unset `OTP_TEST_CODE` for `next start` — the auth package refuses it in production.
- Lint after a build loads `.next/types` (tsconfig includes it) and can run out of memory: lint before building or move `.next` aside.
- Walkthroughs were driven with Playwright scripts (headless Chromium), signing in via `POST /api/auth/sign-in/email`, visiting `/app` first so the active Company is set, then checking figures in the database and screenshots, plus a 375 px overflow check. Screenshots go in `screens/M11/`.
