## Decisions

The fifteen open questions of `modules/03` are answered with recommended defaults in [ADR CM-0013](../../adr/CM-0013-projects-structure-product-decisions.md); attachments and the Gallery in [ADR CM-0014](../../adr/CM-0014-attachments-and-gallery-index.md). Every rule the build settled is in `modules/03-projects-structure-drawings-gallery.md` → "Decisions for the build", by ticket. The ones most worth a look:

- **Project Type is a fixed list** of ten, and it decides Wings or Locations; a Project with rows of the other kind keeps showing them.
- **Contractors and Suppliers ship minimal** (name, contact, mobile, email, address, GSTIN, PAN, Departments for Contractors, active flag, Projects). CM-501 adds quotations and procurement fields. Contacts are not built.
- **Drawings keep revisions**; an album with drawings cannot be deleted.
- **The Gallery is an index, not an upload screen.** Later modules add their photos through `ProjectMediaAttached`.
- **Hidden modules are per Project for everyone; tile order and dashboard layout are per member for every Project; pins are per member per Project.**
- **Unknown ids are 400** (`*_NOT_FOUND`), like the rest of the app, not 422.
- **Thumbnails are made in the browser** and sent before the upload completes, so the thumbnail is recorded in the same transaction as its file (CM-0014, amended).

## Stubs and gaps left for later

- **`StructureUsage` answers "not used"** (`UnusedStructure`). M6 worksheets, M8 issues, inspections and tasks, and M10 bookings must replace it so used floors, units, Wings and Locations cannot be removed.
- **Nothing consumes `LocationRef` yet**; the first site entry (M5 Purchase Request or M6 Daily Worksheet) wires `LocationPicker` and `LocationResolver`.
- **KPI tiles and most dashboard sections are stubs** naming M5, M6, M7, M8 and M10. Progress % on the Project card waits for Tasks (M8).
- **Drawing notifications** (the Notification flag) wait for M9.
- **File routes stream** the file as Documents always did; a signed redirect to Blob is not built.
- **Orphaned uploads** (started, never completed) leave objects in Blob; the M9 clean-up job covers every purpose.
- **Labour and vendor documents** still upload through our routes (≤ 10 MB); moving them onto the attachments service is a separate change.
- **Backups, project chat, RERA fields, unit handover / DLP, tax profile, BOQ budgets and status history** are not in M4 (`modules/03` → Rebuild recommendations).

## How to run and verify

```sh
docker compose up -d
DATABASE_URL=postgresql://whiteboard:whiteboard@localhost:5433/construction bun run --filter @repo/construction-db migrate:deploy
cd apps/construction-management && node_modules/.bin/next dev --webpack --port 3002
bun run --cwd apps/construction-management test
cd apps/construction-management && export $(grep -E "^CONSTRUCTION_DATABASE_URL_TEST=" .env | xargs) && bun run test:http
bun run --cwd apps/construction-management test-storybook
bun run format:check
```

`bun run test:http` does not read `CONSTRUCTION_DATABASE_URL_TEST` from `.env` (the vitest config is evaluated first), so export it as above or the suite runs against the shared `construction_test` database.

Restart the dev server after pulling (new Prisma models).

Verified on the final branch: `check-types`, `lint`, `format:check`; 826 unit tests; 429 HTTP tests on a fresh `construction_test_m4`; 525 Storybook tests (one M3 story, `team-salary-page › Opens A Slip`, failed once in a full run, then passed 3 of 3 alone and in a second full run; it is not M4 code). Each ticket was built on its own branch and database and merged with its own full test run; the whole suite ran again after every merge.

Walked through in the browser on a fresh database: sign up → create a Company → Add Project (Residential, Budget ₹3.2 crore) → Resources opens as step 2 → the project home with tiles and the section bar → Add Wing (Residential & Commercial: 2 commercial floors × 3, 3 residential floors × 4, terrace) → removed unit 103 and added G04 in the editor → saved (7 floors, 21 units) → wing chart → Drawings: the four seed albums, a PNG uploaded to Architect with a browser thumbnail (R1), opened in the viewer → Gallery lists it → Testing Reports: an Rcc cube report dated yesterday with a remark and a file → Amenities: Club House and Compound Wall assigned → Masters → Contractors: an invalid GSTIN refused, then a Contractor added on the Project → Project Dashboard (summary counts, budget, attendance). At 375 px no page scrolls sideways. Two bugs found and fixed on the way: the Project section bar widened every Project page by the sidebar's width (the app shell's main column could not shrink), and the Resources Team Members heading counted 0 above the Owner's row.
