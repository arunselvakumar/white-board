# Student and Parent Workspace invitations

The register is growing beyond the initial P0 scope. A Student remains a Workspace resource in Postgres. If the Add Student form has a Student email address, Whiteboard sends a Clerk Organization invitation with role `org:student`. Father, mother, and Guardian email addresses receive role `org:parent`. Addresses are normalized and deduplicated per Student; the Student role takes precedence if one address appears in both places. Missing email addresses do not block admission and receive no invitation.

The `StudentCreated` domain event is dispatched after the Student is saved. Its in-process listener loads the saved Student and calls a Clerk invitation adapter. Duplicate pending invitations are treated as already sent. A failed invitation is logged and does not prevent the remaining invitations or the saved Student from succeeding. This follows ADR-0008 and does not add a second process or an outbox. Delivery status and automatic retry are not part of this first invitation slice.

Clerk Organization roles `org:student` and `org:parent` have no register permissions. They must be created in each Clerk instance and added to its default Role Set. The development instance has both roles. Production setup must repeat that configuration. The existing register UI routes redirect Student and Parent Users to `/`; their API routes return 403. Only `org:admin` can use them. Root renders a Hello world page for invited roles, and navigation shows one link to `/student` or `/parent` respectively. Invitation links target `/accept-invitation`, where Whiteboard completes Clerk's ticket sign-in or sign-up flow. After any sign-in, sign-up, password reset, or invitation acceptance, Whiteboard routes through Workspace selection. Users with one membership continue automatically; Users with multiple memberships must choose even if Clerk has an Active Workspace already. A switch control in the app header allows choosing another Workspace later. Access and role are always derived from the newly Active Workspace.

This supersedes the P0 statements that Students and family contacts never sign in and that `org:member` staff have the same register access as the Owner. The original P0 PRD remains a historical record.

The Hello world page for Students and Parents is replaced by the Student Home and Parent Home in [ADR-0031](./0031-student-and-parent-home-product-decisions.md).
